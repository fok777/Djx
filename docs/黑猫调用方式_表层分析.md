# 黑猫（Flutter 解析工具 8.0）调用方式 —— 从 ELF 表层结构读出的

本文所有结论均来自 **ELF 导出表 / 导入表 / 字符串常量 / zip 条目** 的直接读取，
不涉及 dex 脱壳。

## 1. radare2：JNI 桥 + 运行时 dlopen

`libr2aibridge.so`（32 KB）导入了 `dlopen` 与 `dlsym`，说明它是
**运行时动态加载** libr_core.so，而不是链接期依赖。这决定了：
必须先 `System.load` 全部 `libr_*.so`，桥才能 dlopen 成功。

### 它只用了 4 个 radare2 API

从 `.dynsym` 的未定义符号（st_shndx=0）读出：

```
r_core_new       创建 RCore
r_core_cmd0      执行不取回输出的命令
r_core_cmd_str   执行并返回字符串（需 free）
r_core_free      释放
```

### 5 个 JNI 方法

```
Java_com_r2aibridge_R2Core_initR2Core
Java_com_r2aibridge_R2Core_executeCommand
Java_com_r2aibridge_R2Core_openFile
Java_com_r2aibridge_R2Core_closeR2Core
Java_com_r2aibridge_R2Core_testR2
```

→ Java 侧必须是 `com.r2aibridge.R2Core`。
日志字符串 `OK: r_core_cmd_str() works, version:` 表明方法返回 `String`。

### 初始化必须执行的 r2 命令（从字符串表读出）

```
e io.cache=true         打开 IO 缓存
e scr.interactive=false 关交互（不关会等输入卡死）
e scr.color=0           关 ANSI 颜色（不关输出全是转义码）
e scr.utf8=0            关 UTF8 框图
e anal.strings=true     分析时抽字符串
```

### 打开文件是双策略

日志字符串：
- `File opened with o: %s`
- `File opened with oo+: %s`
- `All methods failed to open file: %s`

→ 先 `o <path>`，失败退 `oo+ <path>`。

### 它还特意处理了 Android fdsan

```
android_fdsan_set_error_level
SUCCESS: Android fdsan has been DISABLED. No more SIGABRT from double-close!
Could not open libc.so to disable fdsan
```

从 libc.so 里 dlsym 出 `android_fdsan_set_error_level` 并把错误级别调低，
避免 radare2 内部重复 close 同一个 fd 时触发 fdsan 直接 SIGABRT。
这是安卓上跑 radare2 的一个真实坑——不做这步会随机崩溃。

### 加载顺序

`libr_*.so` 之间互相依赖，`libr_util.so` 被 22 个库依赖。
安卓不会到应用私有目录找依赖库，必须按拓扑序手动 `System.load`，
且 `libr2aibridge.so` 必须在 `libr_core.so` **之后**。
顺序见 `Radare2Bridge.LOAD_ORDER`（30 个）。

## 2. 引擎放在 lib/arm64-v8a/，不是 assets/

zip 条目显示 69 个 .so 全部在 `lib/arm64-v8a/`（含 23 个 `libr_*.so`、
23 个 `libblutter_*.so`、`io_frida.so` 125 MB、`libjnidispatch.so`）。

这是因为它清楚：`targetSdk >= 29` 起 SELinux 禁止 untrusted_app
对 `app_data_file`（应用私有目录）执行 `execve()`，chmod 755 无法绕过。
可执行二进制必须在 `nativeLibraryDir`，配合 `extractNativeLibs=true`
由系统安装时提取。

## 3. 各引擎的真实形态

| 组件 | 文件 | 调用方式 |
|---|---|---|
| radare2 | 23 个 `libr_*.so` + 桥 | JNI 桥 dlopen |
| Capstone | `libdisassembler.so` 11.6 KB | `capstone.jni.FastDisassembler`（10 个方法） |
| blutter | 23 个 `libblutter_*.so` | exec PIE 可执行文件 |
| unidbg | `libjnidispatch.so` + `libunicorn_java.so` | **JNA**，ART 上直接跑，不需要 JVM |
| frida | `io_frida.so` 125 MB | gadget |
| Unicorn | `libunicorn.so` 3.5 MB | JNI |

**纠正一个之前的误判**：unidbg 是 JVM jar，我曾判断"安卓 ART 跑不了，
需要装 JVM 或 Termux"。错。`libjnidispatch.so` 导出 69 个
`com.sun.jna.Native.*`，说明它用 JNA 在 ART 上直接跑，无需任何外部运行时。

## 4. 保活：四个广播 + 前台服务

AXML 字符串池读出它注册了：

```
BOOT_COMPLETED
LOCKED_BOOT_COMPLETED
MY_PACKAGE_REPLACED
QUICKBOOT_POWERON
```

配合前台服务（`PROPERTY_SPECIAL_USE_FGS_SUBTYPE`，
描述为 "MCP server running as foreground service to maintain persistent
connection with Claude for code analysis tools"）、
`stopWithTask=false`、`extractNativeLibs`、`largeHeap`。

这是它比旧版稳的原因之一：开机自启 + 包更新自启。

## 5. frida 模板（Dart AOT hook）

`res/raw/frida_template.js`：

```js
const PointerCompressedEnabled = true;
const CompressedWordSize = 4;
const HeapAddressReg = 'x28';
const NullReg = 'x22';
const StackReg = 'x15';
```

按 Dart 带标签对象格式解析（堆指针在 x28，null 在 x22），
可打印对象字段值。这是 Flutter 动态 hook 的关键。

## 6. dex 是加壳的（本轮未碰）

`classes.dex` 12.4 MB，但 header 只声明 3 个类、data 段 9.6 KB。
offset 13084 之后有 12.1 MB 未被 dex 结构声明，熵 6.13，非单字节 XOR。

→ 业务实现（工具注册/分发/参数绑定）看不到。
但**调用方式不依赖它**：上面 1–5 节全从 ELF 表层结构读出，
已足够正确调用 radare2 / blutter / frida / unidbg。
缺失的只是"它自己的调度代码怎么写"，这部分用开源参照
（radare2 官方文档、SoMCP）补齐即可。
